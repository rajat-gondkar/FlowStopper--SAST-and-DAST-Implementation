# Setup & two-person workflow

This guide gets a fresh machine from zero to a green `make check`, and explains how Person 1 and
Person 2 collaborate without stepping on each other. If you only read one thing: run
`make setup && make check && make doctor`.

## Prerequisites

| Tool | Version | Why |
|---|---|---|
| Python | **3.11+** (3.12 recommended; pins were resolved on 3.12) | the tool and tests |
| git | any recent | version control |
| Docker + Compose | recent | mock apps, the one-command demo, scanning the organisers' app (Phase 5) |
| make | GNU make (macOS ships 3.81; fine) | task runner (optional — you can run the commands by hand) |

Check your machine any time with `make doctor` (it also flags lock-file drift, busy ports and
rule-R5 hygiene). On macOS, `python3.12` comes from Homebrew (`brew install python@3.12`).

## Person 1 — initialise and push (once)

> **Pushing is always done by a human (Person 1), never by an AI agent.** Kiro commits locally only;
> it will not run `git push`, create a remote, or push tags on your behalf. Run the commands below
> yourself.

Person 1 already built the scaffold. To publish it:

```bash
cd FlowStopper
git init -b main
git add -A
git status                      # sanity: NO target_src/, keys/, .venv/, *.db, *.local.md
git commit -m "Phase 0: scaffold, frozen contracts, fixtures, test harness"

# create the remote (GitHub CLI shown; or make an empty repo in the UI and add the remote)
gh repo create FlowStopper --private --source . --remote origin --push
# without gh:
#   git remote add origin git@github.com:<you>/FlowStopper.git
#   git push -u origin main

git tag contract-v1 && git push origin contract-v1   # after Person 2 signs off on the contracts
```

Keep the repo **private** (rule R5). Invite Person 2 as a collaborator.

## Person 2 — clone and run

```bash
git clone git@github.com:<person1>/FlowStopper.git && cd FlowStopper
make setup        # .venv + pinned deps (requirements-dev.lock) + editable install
make check        # ruff + pytest, must be green
make doctor       # confirm the environment
```

That reproduces Person 1's environment exactly: same dependency versions (from the lock files),
same package, same passing tests. If `make check` is green you are ready to start
[`PERSON_2_DEV_B.md`](PERSON_2_DEV_B.md).

### Why it reproduces exactly
- **Pinned deps:** `requirements.lock` / `requirements-dev.lock` fix every version (incl.
  transitive). Regenerate only with `make lock` (commit both files + the `THIRD_PARTY.md` update).
- **Pinned interpreter:** `.python-version` records 3.12; stay on 3.11+.
- **Deterministic line endings:** `.gitattributes` forces LF so stable IDs (sha hashes) match on
  every OS.
- **Generated artefacts are checked in and verified:** `fixtures/*.json` and `docs/schemas/*.json`
  are regenerated by scripts and a test fails if they drift (`make fixtures`, `make schemas`).

## Daily git workflow (both)

Trunk-based, short-lived branches:

```bash
git checkout main && git pull
git checkout -b a/P1-A1          # a/<task-id> for Dev A, b/<task-id> for Dev B
# …work… ; keep commits small
make check                       # must pass before you merge
git checkout main && git pull && git merge --no-ff a/P1-A1 && git push
```

Rules of the road:
- **Agents never push.** AI agents (Kiro) commit locally only; a human runs every `git push` and
  pushes tags. If you drive an agent, do the `git push` / `git merge` to `main` yourself.
- **Never edit the other dev's files** (ownership in [`PLAN.md`](PLAN.md)). If you need a shared-
  contract change, append to [`CONTRACT_CHANGES.md`](CONTRACT_CHANGES.md) and get an ack first.
- Update [`PROGRESS.md`](PROGRESS.md) at the end of every task; log any judgement call in
  [`DECISIONS.md`](DECISIONS.md).
- Dev A must **not** open `apps/mock_b/` until Phase 6 (it is the held-out generalisation test).

## Bringing in the organisers' app and answer key (rule R5)

These are confidential and **must never be committed**. `.gitignore` already excludes them.

```bash
mkdir -p target_src keys
cp -R /path/to/organisers_app/*   target_src/      # their source (read-only to the scanner)
cp    /path/to/their_answer_key   keys/            # converted to our schema in Phase 3
cp docs/target_notes.template.md  docs/target_notes.local.md   # fill in locally; git-ignored
```

Verify nothing confidential is staged: `git status --ignored` should list `target_src/`, `keys/`
and `docs/target_notes.local.md` under *Ignored files*. `make doctor` checks this too, and
`tests/test_repo_rules.py` fails the build if they are ever tracked.

Scan it (once the engines land, Phase 3+):

```bash
export ALLOWED_HOSTS="localhost,127.0.0.1,<compose-service-name>"
FlowStopper scan --source target_src --target http://localhost:<port> --out out/
```

## Mock apps (our own fixtures)

```bash
docker compose -f apps/mock_a/docker-compose.yml up   # Mock A (Flask), Phase 1

```

Default dev ports: Mock A `5050`, Mock B `8090`, FlowStopper API `8000` (macOS reserves `5000`
for AirPlay, so Mock A avoids it).

## Troubleshooting

- **`make: command not found`** — open the `Makefile`; each target is a short command sequence you
  can paste.
- **Wrong Python picked up** — `make setup PYTHON=/opt/homebrew/bin/python3.12`.
- **`make check` fails on fixtures/schemas drift** — run `make fixtures && make schemas`, review the
  diff, commit it.
- **Lock drift reported by `make doctor`** — your `.venv` doesn't match the lock files; re-run
  `make setup` (or `make lock` if you intentionally changed dependencies).
- **Ports busy** — stop the other process or change the port in the compose file / `--port`.
