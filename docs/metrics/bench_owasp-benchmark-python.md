# Third-party benchmark: OWASP Benchmark for Python (`owasp-benchmark-python`)

A development benchmark (rule R8), never part of evaluation. Setup and key:
[`bench/owasp-benchmark-python/README.md`](../../bench/owasp-benchmark-python/README.md). Choice:
decision A-70 in [`../DECISIONS_Dev1.md`](../DECISIONS_Dev1.md). The first run is frozen in
[`bench_owasp-benchmark-python_first_run.json`](bench_owasp-benchmark-python_first_run.json).

## Research and choice

We wanted a public, intentionally vulnerable Flask, Django or FastAPI app whose **official
solution** documents 20–30+ vulnerabilities in our scope.

Scores:
- **(a)** in-scope vulns documented by an official solution;
- **(b)** licence;
- **(c)** Python 3 + Docker;
- **(d)** routes our extractors read;
- **(e)** last push (GitHub `pushed_at`, read 2026-11-01);
- **(f)** official decoys.

| Candidate | (a) | (b) | (c) | (d) | (e) | (f) | Verdict |
|---|---|---|---|---|---|---|---|
| [OWASP BenchmarkPython](https://github.com/OWASP-Benchmark/BenchmarkPython) | **151** (127 pair + 24 cookie) from `expectedresults-0.1.csv` | GPL-3.0 (local use only) | Py 3.12, own Docker wrapper | Flask, nested in `init(app)` | 2026-05-19 | **215** | **Chosen** |

Why BenchmarkPython was chosen:
- It is the only single app with more than 20 in-scope vulns in an official, machine-readable
  solution. It also has official known-safe cases (decoys), runs on Python 3.12, and needs no login.
- GPL-3.0 obligations attach to distribution, and we only clone it locally to scan it.

Trade-offs:
- It is a synthetic per-flow suite (one small route per test), not a realistic multi-feature app.
- Many flows read headers and cookies.

Full notes and sources are in A-70.

**Keyed:** 151 vulns (127 pair, 0 code_only, 24 runtime_only) and 215 decoys
(`bench/owasp-benchmark-python/answer_key.json`, generated by `build_key.py` from the official CSV).

## First run (frozen, before any change)

2026-10-31, Docker on `127.0.0.1:8110`. The app returned HTTP 200 before the scan started. No auth
config was needed.

```bash
.venv/bin/FlowStopper scan --source bench/owasp-benchmark-python/src --target http://127.0.0.1:8110 \
    --out out/owasp-benchmark-python_first
.venv/bin/FlowStopper eval --key bench/owasp-benchmark-python/answer_key.json \
    --issues out/owasp-benchmark-python_first/issues.json \
    --out docs/metrics/bench_owasp-benchmark-python_first_run.json
```

| Metric | Count | Value |
|---|---|---|
| Code detection | 0/127 | 0.0% |
| Runtime detection | 0/151 | 0.0% |
| Correct links | 0/127 | 0.0% |
| Wrong links | 0/0 | n/a |
| False alarms | 0/5 | 0.0% |
| Run time | | 48.1 s |

The scan found 3 routes, 2 SAST findings and 7 DAST findings, and produced 5 issues. None of the 5
matches a planted vuln or a decoy: 2 hard-coded LDAP passwords in `helpers/ldap.py`, plus host-wide
verbose-error, version-banner and missing-header findings. None of these is in the official solution.

**Why everything was missed:** the Flask route extractor does not read routes registered on a
function parameter (`def init(app): @app.route(...)`). So only `app.py`'s own 3 routes were found,
taint analysis never ran on the 1,230 handlers, and DAST had no seeds for them.

A line-preserving probe copy (in `out/`) moves the routes onto a module-level app. With that copy,
the unchanged scanner scores code 51/127, runtime 22/151, links 12/127, wrong links 0/19 and false
alarms 77/745. That is the ceiling for fixing only the route idiom (triage T1).

## Triage

Root causes were confirmed with:
- the probe copy;
- 40 one-idiom Flask handlers scanned by the unchanged SAST;
- `curl` and `docker exec` against the container;
- reading the scanner code.

Details and per-entry data are in `out/wf_bench_new/triage.md` (git-ignored). The table is ranked
by cost per safe gain. Gains are estimates measured against the probe copy.

| Rank | Item | Bucket | Root cause | Est. gain | Cost | Fixed / deferred |
|---|---|---|---|---|---|---|
| 1 | T1 nested `init(app)` routes | framework idiom not supported (SAST route miss) | `routes/flask.py::_resolve_obj` never treats a function parameter as a Flask app; the `importlib` call site is dynamic | code +51, runtime +22, links +12 | S–M | **Fixed** (A-71) |
| 2 | T2 traversal proof HTML-encoded | DAST miss | `checks/traversal.py` matches `root:x:0:0:` on the raw body; the app echoes `root&#x3a;x&#x3a;0...` | runtime +6, links ≈+3 | XS | **Fixed** (A-72) |
| 2 | T3 `/etc/passwd` truncated during scan | bench environment | write-mode traversal tests run as root in our container and truncate the proof file (839 → 0 bytes in one scan) | needed for T2 | S (our Dockerfile: non-root user) | **Fixed** (our Dockerfile, A-71) |
| 3 | T10 value in a response header flagged as XSS | false alarm | `make_response((body, {hdr: v}))`: the whole tuple feeds the CWE-79 sink | FA −7 | S | **Fixed** (A-73) |
| 4 | T4 `break` inside `if` in a loop | SAST miss (engine bug) | `engine._stmt` treats `break` like `return`, so `_if` discards the state before it | code ≈+8–11 | S | Deferred |
| 5 | T5 `request.query_string` | SAST miss | not in `sources.CONTAINERS` | code ≈+6 | XS | Deferred |

| 7 | T6 `["sh", "-c", cmd]` argv | SAST miss + suppression error | list form is suppressed as `safe:subprocess-list-no-shell` even when argv[0] is a shell with `-c`; appended lists also need T8 | code +1 (≈+6, links +3 with T8) | S / M | Deferred |
| 8 | T7 existence checks | SAST miss | `os.path.exists/isfile`, `Path.exists` are not traversal sinks | code ≈+6 | XS (FA risk: 24 decoys) | Deferred |
| 9 | T8 dict / list / ConfigParser / `format(dict)` propagation | SAST miss | container writes and reads do not carry taint; must be key-sensitive (decoys read a safe key) | code ≈+29 | M–L | Deferred |

| 12 | T14 params read through a helper | DAST miss | `_RequestScan` sees only direct `request.*` reads, so DAST never gets the param name | runtime ≈+10 | M | Deferred |

Not fixable within the rules:
- **Blind traversal:** 19 of the 25 keyed CWE-22 vulns that take a form/query param only check
  existence, open without reading, or open for writing. The only proof R4 allows is the content of
  `/etc/passwd`, so these cannot be shown.
- **Name-as-payload loops:** in `form.keys`/`headers.keys` loops the parameter name carries the
  attack value, and DAST mutates values only.

Other categories:
- **Wrong links:** 0 in the first run, and 0 of 19 confirmed in the probe.
- **Link misses:** none of their own. Every probe pair with both a code and a runtime hit is linked.
  The 10 pairs with a runtime hit but no link all lack the code hit (T6/T8).
- **Suppression errors:** none on this benchmark.

## Round 1 fixes

Goal: on this benchmark, code ≥ 40/127, runtime ≥ 25/151, links ≥ 12/127, 0 wrong links and
fewer false alarms than the probe's 77, with Mock A, Mock B and we45 unchanged. The goal was met.

| Triage | Rule | Files | Tests |
|---|---|---|---|
| T1 (A-71) | In a module that imports Flask, a function parameter used as the receiver of a route decorator or `add_url_rule` is a mountable object. Static call sites that pass a known app or blueprint mount it there; otherwise it mounts at the root. | `FlowStopper/sast/routes/flask.py` | `tests/test_sast_routes.py::test_flask_routes_registered_on_a_function_parameter`, `::test_parameter_router_outside_flask_is_not_a_flask_route` |
| T2 (A-72) | The traversal proof is also matched on `html.unescape(body)`, in the probe, the baseline guard and the verify control. | `FlowStopper/dast/checks/traversal.py`, `FlowStopper/dast/verify.py` | `tests/test_checks_p2.py::test_traversal_detected_through_html_entity_encoding` |
| T3 | Our bench image runs as the non-root user `bench` (uid 10001), which owns `/app`. | `bench/owasp-benchmark-python/Dockerfile` | live: `/etc/passwd` still 880 bytes after the full scan |
| T10 (A-73) | For a literal tuple `make_response((body, ...))`, only the body feeds the CWE-79 sink. | `FlowStopper/sast/taint/engine.py` | `tests/test_sast_taint.py::test_make_response_tuple_only_the_body_is_html` |

## Before / after (all four targets)

All four apps ran in Docker and returned HTTP 200 before each scan. The we45 bench was scanned with
`--auth-config out/b/auth.json`. Commands are in `out/wf_bench_new/stage4_record.md` (git-ignored).
This benchmark's "before" is the frozen first run. Mock A, Mock B and we45 were rescanned before
any code change.

| Target | Code | Runtime | Links | Wrong links | False alarms |
|---|---|---|---|---|---|
| OWASP BenchmarkPython, before (first run) | 0/127 | 0/151 | 0/127 | 0/0 | 0/5 |
| OWASP BenchmarkPython, route probe (unchanged scanner, reference only) | 51/127 | 22/151 | 12/127 | 0/19 | 77/745 |
| OWASP BenchmarkPython, after | 51/127 | 28/151 | 15/127 | 0/22 | 68/739 |
| Mock A, before = after | 13/13 | 12/13 | 9/10 | 0/9 | 0/19 |
| Mock B, before = after | 13/13 | 11/14 | 8/10 | 0/8 | 0/19 |
| we45, before = after | 4/4 | 3/3 | 1/2 | 0/1 | 0/11 |

- For Mock A, Mock B and we45, the sorted `(issue id, label)` sets are identical before and after.
  No fix was reverted.
- The after scan of this benchmark took 99.8 s. It found 2,463 routes, 768 SAST findings and 37
  DAST findings, and reported 739 issues (22 confirmed, 701 code-only, 16 runtime-only) plus 47
  suppressed.
- After, per CWE (code / runtime / links): 22: 23/6/3, 78: 4/6/2, 79: 15/12/7, 89: 2/1/0,
  601: 7/3/3, 614: 0 runtime.
- Environment change: the "after" container runs as a non-root user (T3), so write-mode test cases
  can no longer truncate `/etc/passwd`. The extra runtime and link gains over the probe (+6
  runtime, +3 links) come from T2, which needs this. The first run and the probe ran as root.

## Deferred for the next round

Ranked as in the triage table:
1. **T4** `break` inside an `if` in a loop discards the earlier assignment (engine bug). Code ≈+8–11, cost S.
2. **T5** `request.query_string` is not a source. Code ≈+6, cost XS; 12 decoys may start alarming.
3. **T11a** `resolve()` then `startswith` through a variable is not seen as a guard. FA ≈−9, cost S.
4. **T6** `["sh", "-c", cmd]` argument lists are wrongly suppressed as list-form subprocess calls.
   Code +1 alone, ≈+6 and links +3 with T8. Cost S / M.
5. **T7** `os.path.exists`, `os.path.isfile` and `Path.exists` are not traversal sinks. Code ≈+6,
   cost XS; 24 decoys may start alarming.
6. **T8** taint through dict, list, ConfigParser and `format(dict)`, tracked per key. Code ≈+29, cost M–L.
7. **T9** constant folding for branch conditions. FA ≈−37, cost M–L.
8. **T11b** `'../' in x` as a guard, for string concatenation only. FA ≈−11, cost S.
9. **T14** parameter names read through a helper function are not passed to DAST. Runtime ≈+10, cost M.
10. **T12** the upstream char-by-char HTML encoder is not a sanitiser (A-07 forbids trusting it by
    name). 589 unkeyed issues and 2 FAs. Cost L.
11. **T13** a GET handler that returns the POST handler reports the same flow twice. FA −14, cost M.
12. **T15** DAST never injects headers or cookies (41 header and 11 cookie keyed vulns). Cost L.
13. **T16** CWE-614 is 0/24: the Secure flag is skipped over HTTP (B-04), and the cookie checks
    sample 5 GET pages and report one host-wide finding. Cost L.
14. **T17** the crawler stops at depth 3 and 300 URLs. It no longer matters after T1. Cost S.
